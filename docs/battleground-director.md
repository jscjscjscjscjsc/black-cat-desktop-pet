## 在新长语音/对话中使用

- “打开炉石酒馆战棋”：模型可用 `battleground(action=open)` 打开/切回游戏，登录仍由用户完成。
- “帮我执行一步战棋操作”：`step`，后台依据日志候选、现有 DeepSeek 和视觉模型执行一项受支持动作。
- “接管当前招募，最多十二步，运行四分钟”：`auto`，单次最多 30 步、300 秒。默认 12 步、240 秒；不会创建无限任务或后台持续运行数小时。
- “只观察战棋，不要操作”：`observe`，仅增量读取日志，不发鼠标输入。
- “看看当前游戏画面”：`look`，截图只限游戏客户区，交给已有视觉模型观察，不生成操作；可继续聊天询问状态中的观察结果。
- “读取内存里的棋盘”：`memory`，独立短进程调用本机 HearthMirror 棋盘读取方法，12 秒超时终止。不是内存写入/函数调用后端。
- “查看战棋任务状态”/“停止接管”：`status` / `stop`。停止按钮、关闭智能体窗口、结束长语音同样请求停止；正在返回的模型结果不会触发新输入。

启动响应只是任务已受理。真正的执行回执、暂停原因和复盘由后台事件返回，挂到启动任务的原会话。语音连接保持原有千问实时连接，不另开连接、不切换到普通 Edge TTS。普通 Edge TTS 功能继续保留。

## 数据、执行和播报分工

`core/bg_live.py`：Power.log 增量局面、合法候选、DeepSeek 决策、视觉定位和动作回执。现有单步/旧实战窗口与新后台共享互斥锁，不能同时发送输入。日志明确显示战斗阶段时拒绝招募动作。后台只在明确战斗→招募转换时称“战斗结束”；普通任务结束单独说明，不能混称打完一局。

`core/bg_director.py`：后台线程与有限预算、观察模式、结构化事件、会话绑定与有依据的复盘。只把 `verified=True` 的动作计入完成数量；入口/英雄点击没有服务端回执时只记录“输入已发送”，不自动重复。复盘使用当时模型保存的理由，说明它不构成胜负因果证明。冻结切换后主动停止，避免来回切换。

`core/bg_memory.py`：仅投影卡牌 ID、实体 ID、位置；不导出账号、昵称或无关内存。将本机 HearthMirror DLL 固定到已检查 SHA256 `3cc1180b89582127fe737d0a8c6e03f13d460437a43511a6fc382bc958f31d1d`，更新后必须重新核对接口。原生读取只在子进程运行，Qt 不加载 CLR。首次实测返回空棋盘，故**未证明当前客户端的内存读取已成功**。状态明确显示 `memory_execution_available=False`；尚无已验证的直接内存操作后端。

`core/realtime_agent.py`：将后台事件加入现有语音会话，等用户停止说话、当前回答和音频播放结束后播报。去重、90 秒过期、打断失效；后台播报中的模型工具请求被拒绝，不会因一条复盘又启动新的下棋任务。该路径使用平台文档的 `conversation.item.create` 与 `response.create`，见[千问实时语音客户端事件](https://docs.qwencloud.com/api-reference/qwen-audio-realtime/client-events)。

用户对真实游戏窗口截图的既有授权继续用于视觉定位；只发送游戏客户区，不增加全桌面采集。没有给实时语音模型上传屏幕视频：结构化局面与截图定位分别由现有决策/视觉模型处理。未复用炉石盒子未还原的管道协议，也未注入游戏进程。

## 八席模拟和训练

```powershell
python tools/bg_selfplay.py --engine 'C:/Users/Admin（无密码）/Desktop/Vibe oding/output/guga-selfplay-lab-20261016/HSBRSIM' --games 1 --seed 20261019 --cloud-calls 8 --cloud-ledger 'runtime/bg-lab/your-phase-budget.json' --output 'runtime/bg-lab/new-expert-battles.json'
python tools/train_bg_selfplay.py --engine 'C:/Users/Admin（无密码）/Desktop/Vibe oding/output/guga-selfplay-lab-20261016/HSBRSIM' --expert-battles 'runtime/bg-lab/new-expert-battles.json' --output 'runtime/bg-lab/new-expert-training' --bc-games 1 --rl-games 2 --eval-games 8 --max-seconds 90
```

输出路径须新建。八个席位拥有各自策略上下文，云端共享显式请求预算，从第 3 回合起，每席每回合至多一次专家选择；其他动作由规则策略完成并标注来源。不是八个大模型每步无限请求。`--cloud-calls` 默认 0，最大 128，消耗已配置的官方 Go 模型套餐；HTTP/解析/候选验证失败后停用本次云端，不重试、不切换服务。只将该席可见棋盘、手牌和商店发给模型，不泄露其他席位隐藏信息。

`core/bg_expert_data.py` 校验 profile、引擎提交、完整对局、候选索引及有限特征。专家监督使用模型选择的合法动作索引，模型解释文字不作为训练标签，也不代表该选择最优。源轨迹哈希记入训练报告；评测种子与训练分离。

依然是旧 `hsrl2-neutral-minion-lab-v1` 规则子集，不支持完整当前天梯、全部英雄技能/法术/站位/新版本机制。卡池与规则差异见 [离线实验室说明](battleground-selfplay.md)。本地权重不会自动替换当前实战 DS 决策器，更不会把离线名次换算为天梯段位。
