# 咕嘎实战操作第一阶段

2026-10-19。目标从观察推进到实际操作；当前已实现有明确预算的执行入口，实机成功回执仍待验证，不能声称已经完成自动代打。

## 启动与使用

1. 本机炉石以管理员身份运行，Windows 会拦截普通权限桌宠发来的输入。手动右键 `启动战棋实战.bat`，选择以管理员身份运行；不修改系统安全设置。
2. 窗口提供打开/切回炉石、模型执行一步、限时连续操作。连续模式至多 12 步、4 分钟输入预算，按住 Esc 或点击停止中止。模型请求返回可能稍后于预算，但预算到期后不再发新输入。
3. 桌宠右键只保留四类：一键拔线、对话、日志分析、战局分析/实战操作。退出仍在系统托盘；长语音与语音设置在对话子菜单。
4. 对普通文字对话说“打开酒馆战棋”，白名单命令路由会打开游戏并调用现有模型选择可见免费入口；说“帮我操作下棋”会打开有限执行。不是任意模型文本都能运行命令；这两种明确请求才可触发。

尚不自动处理战网认证/更新、选目标法术、发现弹窗与完整回合。免费入口和英雄选择一次点一步，排队后或进入招募后重新点执行。英雄选择依据画面里的已解锁候选、技能描述和模型判断；尚无当前版本已核验的英雄大数据胜率表，不包装成数据排名。

## 读取、决策、定位和回执

`core/bg_live.py` 增量重放白名单 Power.log，提取服务端候选及错误码为 NONE 的目标，通过招募辅助实体确认本方控制器。只生成受支持的买/出/卖随从、刷新、冻结和升本候选；不假定新版本特殊效果已经完整模拟。

决策使用原 `ai_config.json` 配置中的 `deepseek-v4.1-flash` 和官方 Go URL，不改 Key，不使用 CLI 映射。选择限定为候选 ID；原有 GLM 视觉接口负责当前游戏窗口中具体动作的位置和阶段，置信不足时不执行。视觉定位并非已经通过真实点击验证的能力，当前仍需实机校准。

`core/bg_live_windows.py` 是桌宠自身的窗口/鼠标后端，按 Hearthstone.exe 进程筛选唯一窗口。执行前检查权限、焦点、窗口尺寸、遮挡、停止键，以及模型思考前后的局面指纹。只截取游戏客户区，没有全桌面兜底。产品功能测试中的助手 UI 操作使用 computer-use 技能。

招募动作执行后，要求客户端 SendOption 与当前候选代次/目标对应，且出现相应区域、等级或状态变化；没有确认就停止，不盲目重试。入口/英雄点击只标记为视觉输入已发送、未获服务端回执，不能混称执行成功。三连导致买入实体立即消失、发现弹窗等情况可能暂停，需要补专门适配。

本机审计仅包含动作、模型理由、用量、局面指纹与确认标记，保存在被 Git 忽略的 `runtime/bg-live/`；不保存截图、录音、API Key、HTTP 内容或原始账号日志。

## 本次验证及限制

- 57 项离线测试通过：包括候选/目标代次、满场、过期局面指纹、战斗/低置信度拒绝输入、选择与状态双重回执，以及日志、语音和已有模型配置相关回归。
- 新面板第一次直接启动遗漏 Qt 路径初始化，出现用户截图中的平台插件错误。已复用现有 `_prepare_qt()`，新入口第二次能正常显示；`main.py` 直接启动也补齐同样初始化。提权重启会转发 `--bg-live` 和 `--voice`。
- 实机查看到酒馆战棋大厅；助手的两次点击与键盘验证没有开启匹配。只读进程令牌检查确认 Hearthstone elevated=1、测试 Python elevated=0，符合 Windows 输入权限边界。没有成功购买、出牌、升本或开始新对局的回执；用户已表示将手动以管理员启动咕嘎测试。
- 千问实时语音服务测试：文本输入返回 4.24 秒音频、首段 1.08 秒；另一次合成语音输入 2.96 秒，返回 6.48 秒音频、首段 1.95 秒。接口配置成功，原免费用尽即停确认继续生效；本轮接口探测合计报告 707 tokens（224+202+281）。没有录取用户语音，麦克风/扬声器格式检查通过，真实麦克风长聊仍待用户验证。
- 普通 Edge TTS 未改；未更改模型 Key、系统权限设置或开启自动充值。

## 阵容与胜率

已查阅 [36.6 官方公告](https://hearthstone.blizzard.com/en-us/news/24294373) 与 [HSReplay 当前阵容入口](https://hsreplay.net/battlegrounds/comps/)。官方改动公告不能当胜率排名，当前访问未取得可核验的完整阵容强度表。`data/bg_agent/live_strategy.json` 明确标注没有排名数据；使用已有核心、实际来牌、即时战力、经济和触发链的条件策略。

日志分析入口显示 HDT 本机记录的双方阵容、模拟胜/平/负、实际结果及来源最后更新时间；仍未自动对齐当前场次。没有调用咕嘎旧简化模拟器来伪装 HDT 当前胜率。

用户提到的炉石盒子逐步决策评估与单次战斗模拟是不同目标：前者需要对购买、出售、站位、刷新/升本后的分支局面进行合法推演，再比较收益；后者估计给定双方阵容的战斗结果分布。尚未取得盒子内部算法、源码或可用接口，不能声称已经复现。
